# Chunk transition performance

The high-refresh target is native display frequency, without reducing visible quality. Camera turns previously invalidated occlusion and relief whenever the region's sector key changed, even for empty sectors. A sparse CPU-only sector index now prepares block/ground references on edit, scopes occlusion to occupied sectors, and includes actual liquid and ground selection in the geometry key. Offscreen relief batches are detached and retained within bounded instance/batch budgets. Ground descriptors for nearby inactive sectors are prepared in small idle slices where supported, never forcing an idle callback timeout. No additional GPU draw calls are issued for parked meshes.

The first visit to an uncached dense sector can still cause synchronous geometry creation and GPU upload. This is not a full worker-driven voxel mesher or a visual LOD system. Measure frame time p95 and worst interval while rotating and crossing sectors at unchanged settings. Exposed diagnostics: terrainPreloads, reliefBuilds, occlusionBuilds, parkedReliefBatches.
## Rotation stability

Resident geometry now uses the configured far radius in all directions, with a four-cell boundary hysteresis and guard band. The legacy cone is no longer used for streaming; Three.js still frustum-culls the camera view, and the visibility shader is unchanged. This trades some additional resident geometry (and potentially initial loading cost) for no sector rebuild on pure rotation. Liquid meshes are retained while their actual selection and source result are unchanged. Instance picking rejects nonintersecting chunk bounds before building a cold acceleration index. The HUD reports the largest measured CPU phase over the rolling window; WebGL submission time is not a GPU timer.

## Translation and local occlusion

A measured 55.2 ms occlusion spike on chunk translation motivated an exact sector cache. Build the sparse world occlusion index once per geometry revision, slice and view mode; retain up to four residency variants per occupied sector. A conservative one-cell halo plus spatially indexed placed-block footprints tracks which neighbors can change occlusion. Unchanged interior sectors reuse their results, and reentering a cached region does not rerun face coverage tests. The renderer retains the existing region-relative face rules and still includes only active occluders. The first world index build after geometry edits remains synchronous; a first visit to a dense sector can still cost time, and merging results and relief planning still run on region changes. Counters: occlusionIndexBuilds, occlusionChunkBuilds, occlusionChunkHits. No GPU quality or frame-rate cap is changed.
